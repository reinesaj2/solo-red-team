Detailed Password Hash Analysis (Field 2):
------------------------------------------
**Question (b): For fields containing multiple parts separated by '$', explain each part.**

Complete Hash: $6$ykumbyCz$IiKc0RFh2Xa/uV9H8Ayed9aHSSAPEWx0LI8GMtaGrJX61iuYa2Qdw.8rt2bxnZPZgBqm2To26K7a/YDfbTsY61

**Part 1: Hash Type Identifier**
- Value: "$6"
- Purpose: Identifies the hashing algorithm used
- Meaning: SHA-512 based crypt(3) algorithm
- Alternative values: $1=MD5, $2=Blowfish, $5=SHA-256, $6=SHA-512

**Part 2: Salt**
- Value: "$ykumbyCz"
- Purpose: Random value added to password before hashing
- Format: Base64-like encoding using ./0-9A-Za-z alphabet
- Length: 8 characters (can be up to 16)
- **Critical Security Feature**: Unique per password, prevents rainbow table attacks

**Part 3: Hash Value**
- Value: "$IiKc0RFh2Xa/uV9H8Ayed9aHSSAPEWx0LI8GMtaGrJX61iuYa2Qdw.8rt2bxnZPZgBqm2To26K7a/YDfbTsY61"
- Purpose: Final password hash after salt and iteration processing
- Format: Base64-like encoding of 512-bit SHA-512 output
- Length: 86 characters
- **Process**: Result of SHA-512^5000(password||salt)

COMPARATIVE SECURITY ANALYSIS
=============================

**Hash Security Ranking (Strongest to Weakest)**:
1. **Linux SHA-512**: Individual salt + 5000 iterations + strong hash
2. **Windows NTLM**: Strong hash function but no salt or iterations
3. **Windows LM**: Multiple fundamental vulnerabilities

**Field Complexity**:
- **Windows**: Simple colon-separated format, minimal metadata
- **Linux**: Rich metadata including shell, directories, and user info

**Password Reuse Detection**:
- **Windows**: NTLM hash duplication reveals identical passwords
- **Linux**: Salt prevents detection of identical passwords (by design)

**Attack Surface**:
- **Windows 7**: NTLM hashes only (LM disabled)
- **Windows 2003**: Both LM and NTLM active (double vulnerability)
- **Linux**: Single strong hash format with computational protection

KEY LEARNING OUTCOMES
=====================

1. **Evolution of Security**: Clear progression from LM → NTLM → SHA-512
2. **Salt Importance**: Linux individual salts vs Windows no salt
3. **Computational Security**: Linux iteration count vs Windows single hash
4. **Hash Duplication**: Windows reveals password reuse, Linux protects privacy
5. **Field Richness**: Linux includes full user environment data

This analysis demonstrates why modern systems use salted, iterated hash functions and explains the dramatically different attack success rates observed in the practical cracking phases of this project.
